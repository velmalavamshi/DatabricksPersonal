## Correction to the source brief (2026-09-19)

The pasted brief's "Current High-Level Architecture" section lists SSE events as:
`content, status, thinking, tool_call, tool_result, sql_result, image, error, done, tool_call_pending, workspace_asset_created`

**This does not match the deployed app.** The real, test-verified contract — frozen from the *deployed* Workspace copy, 164 pytest+node tests green, see Phase 15's `phase0_baseline/contract_sse_stream.md` (`/5 - AI Multi Agents/0 - All files/NEXUS_V4_Upgrade/`) — is:

`routing, progress, delta, tool_trace_step, tool_call_pending, asset_created, image, job_status, final_text, error, done` (11 events)

Any contract work in sub-phases 1/3 below must use `phase0_baseline/` as the source of truth, not the brief's inventory — this is exactly the "spec vs. reality" drift the brief itself (correctly) warns against.

Route count/categorization in the brief (~63 routes, 37 GET/20 POST/6 DELETE) **does match** the frozen contract — that part can be trusted as-is.

One more inconsistency to resolve before sub-phase 4 (Durable HITL) starts: Phase 15's own plan doc has two contradictory claims about HITL — its Phase-0 correction says HITL is "Real — front + back," but its own Phase-5 section separately says "HITL doesn't exist today." Neither is quite right for this phase's purposes: HITL is real and functional (`tool_call_pending`/`tool_trace_step`, `resume_state`+`tool_decisions`), but **not durable** — the pause/resume state round-trips through the client, nothing is persisted server-side as an approval entity. That's the actual gap sub-phase 4 closes.
